# 10 认证、权限与用户管理实现记录

记录日期：2026-10-04。本记录只描述第一阶段真实完成和验证的内容；课程、资源、审核、收藏、统计等后续业务尚未实现。

## 实现范围与技术

- 后端：Spring Boot 3.5.7（JDK 21.0.11、Maven 3.9.9）、Spring Security 6.5.6、Spring JDBC、MySQL Connector/J 9.4.0。
- 前端：Vue 3.5.13、Vue Router 4.5.1、Vite 6.3.5（Node.js 22.14.0、pnpm 11.25.0）。
- 数据库：本机 MySQL Server 8.0.39，项目数据库 `management-system`。
- 认证：账号密码经 Spring Security 校验，成功后使用服务端 Session 和 HttpOnly Cookie。写请求使用 CSRF 令牌；登录时更新 Session ID；退出时服务端失效 Session。密码用 BCrypt(12) 散列，数据库及 API 响应均不保存或返回明文。
- 授权：URL 和方法级共同限制 `/api/users` 只允许 `ADMIN`；前端路由守卫和菜单同步限制入口，但不替代后端校验。每次已认证请求重新核验用户状态、角色和账号，禁用或变更角色后原会话失效。
- 用户管理：管理员查询与筛选用户、新增教师/学生、编辑账号姓名及允许的角色、启停非管理员用户。管理员账号不能通过该接口新增或停用。已有创建资源的用户不能改变角色，以维护领域模型中资源创建者的角色约束。

## 数据库与测试数据

沿用 `database/schema.sql` 中的 `role`、`app_user` 及其他既有 11 张表；**本轮新增表 0 张、新增字段 0 个**。为匹配本机已确认的空库，仅将建表脚本中的数据库名由 `civics_resources` 调整为 `management-system`，未改表结构或关联关系。脚本执行后通过 `information_schema` 查询确认 11 张表。

`database/dev-seed.sql` 加入三个固定角色和 `dev_admin`、`dev_teacher`、`dev_student` 三个本地测试账号；测试密码和仅限本地使用的警示见 README。实际查询三个账号的 `password_hash` 均以 `$2a$12$` 开头，未保存明文。浏览器和接口验证另外产生四个测试账号，均已禁用，未物理删除。真实 MySQL root 连接信息仅放在被 Git 忽略的 `backend/config/application-local.yml`，未写入受跟踪源文件。

## 新增接口与页面

| 接口 | 实际功能 |
|---|---|
| `GET /api/auth/csrf` | 获取当前会话 CSRF 令牌 |
| `POST /api/auth/login` | 账号密码登录 |
| `GET /api/auth/me` | 获取本人资料 |
| `POST /api/auth/logout` | 退出并失效会话 |
| `GET /api/users` | 关键词、角色、状态筛选与分页 |
| `POST /api/users` | 新增教师/学生 |
| `PUT /api/users/{id}` | 编辑用户 |
| `PATCH /api/users/{id}/status` | 启用/禁用用户 |

前端已实际呈现登录页、首页、个人信息页、管理员用户管理页及统一主布局。管理员菜单含“首页、用户管理、个人信息”；教师和学生只含“首页、个人信息”。没有放置课程、资源等尚不可用的假菜单。

## 遇到的问题与处理

1. MySQL 命令行首次执行含中文的开发种子脚本时，客户端字符集不匹配导致角色名称插入失败。设置 `utf8mb4` 后重试成功，并把 `SET NAMES utf8mb4` 写入脚本。
2. 第一次 CSRF 手工测试中，PowerShell 的 `WebRequestSession` 保留了先前请求头，使“无令牌”测试出现误判。清除会话头后重新运行，服务器正确返回 403；最终 26 项断言均通过。
3. 浏览器原生确认框阻断了页面自动化检查，故将启停操作改为页面内确认框；浏览器实际点击启用、禁用并看到状态更新。

## 与设计基线的核对及待办

本轮使用既有单角色 `role`→`app_user` 结构，没有新增多角色授权表。管理员管理用户、教师和学生只读本人信息的权限与 `docs/01`—`docs/03` 一致；其他领域对象及业务表未实现接口。现有设计文档原先使用测试库名 `civics_resources` 的地方属于上阶段验证记录，本轮因用户确认本机目标库为 `management-system` 而只调整连接与建表脚本库名，未改变业务设计。

尚需在进入后续阶段前处理：目前本机连接使用 root，宜改成仅有 `management-system` 所需权限的项目账号；正式环境不得执行开发种子脚本，也不得沿用固定测试账号密码。课程、资源等后续模块须继续以原任务书、开题报告和设计文档为准。
