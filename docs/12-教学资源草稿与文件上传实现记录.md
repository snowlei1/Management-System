## 2. 最终数据库结构

真实库为本机 `management-system`，仍11张表；本轮新增表0、修改字段0、迁移0。既有两表已能满足需求，不修改schema.sql或推翻模型。

`teaching_resource`最终字段：

| 字段 | 既有类型/约束 |
|---|---|
| id | BIGINT UNSIGNED自增主键 |
| title | VARCHAR(200)非空 |
| description | VARCHAR(2000)，可空 |
| course_id / category_id / created_by | BIGINT UNSIGNED非空外键，一门课程、一个分类、Session教师 |
| file_storage_key | VARCHAR(500)非空，服务端生成UUID相对定位键 |

| file_size_bytes | BIGINT UNSIGNED非空，CHECK大于0 |
| status | VARCHAR(16)，默认DRAFT，预留DRAFT/PENDING/APPROVED/REJECTED |
| submission_no | INT UNSIGNED默认0，本轮不变更 |
| published_at / deleted_at | DATETIME(3)，可空；本轮只使用deleted_at进行软删除 |

保留原主键、检索/归属索引及ON DELETE RESTRICT外键。资源创建不接受客户端状态或创建教师ID，服务层写死DRAFT并使用Session教师ID。

`resource_element_relation`沿用resource_id和element_id联合主键、created_at、元素反向索引及两条RESTRICT外键。使用独立关联记录，不存逗号拼接ID；输入去重并按ID排序。草稿无标注时不插关联记录，编辑时在同一事务内整体替换当前标注；软删除资源不清除关联。

后端校验课程、分类、所有选中元素均存在且ACTIVE，使用FOR SHARE锁保持本次保存中状态稳定；编辑/删除先锁定本人资源。历史关联的基础数据停用后，详情仍显示原名称和停用状态；再次保存时须重新选择有效数据或取消停用元素，不会静默删除历史关联。

## 3. 文件存储、安全与限制

在backend目录启动时默认路径为 `backend/uploads/resources`，可通过 `RESOURCE_STORAGE_DIR` 覆盖。数据库只存UUID加扩展名的相对键；实际目录不公开为静态资源，API响应不暴露定位键或绝对路径。本轮没有文件读取/预览/下载业务接口；以后只能从经授权后端读取，不允许前端拼路径。

服务层和Servlet的文件上限均20 MiB，multipart请求上限21 MiB。`RESOURCE_MAX_FILE_SIZE`同时覆盖两处文件限制，`RESOURCE_MAX_REQUEST_SIZE`覆盖请求限制。允许扩展名集中在 `app.resource-storage.allowed-extensions`；规范MIME映射集中在文件存储组件，前端从upload-policy读取限制。

检查包括：非空；声明与真实读取大小；扩展名；相应Content-Type；PDF头及末尾特征、PNG/JPEG签名、旧Office复合文件头与相应流名、OOXML容器及主部件Content-Type。OOXML检查禁止宏部件、危险ZIP条目名、过多条目及过大解压量；XML禁止DOCTYPE和外部实体。**这些不是病毒扫描、完整文档解析或生产安全审计**；不承诺检测全部恶意内容，当前不支持宏或加密OOXML。

原文件名保留中文、内部空格和普通特殊字符，进行NFC归一化并去除首尾空白；拒绝路径分隔符、盘符/冒号、控制/格式字符、无扩展名及过长名称。物理名由UUID生成，CREATE_NEW写入，同名上传不会覆盖。所有内容只进入受控目录，不采用MySQL BLOB、MinIO、云存储或视频基础设施。

## 4. 事务与文件补偿的实际顺序

采用Spring TransactionTemplate，沿用真实MySQL事务管理器；资源和元素关联始终处于同一事务。

1. 创建：规范化元数据→校验/锁定有效基础数据→校验并保存新文件→立即登记事务回调→插入DRAFT资源→写元素关联→提交数据库。
2. 修改：锁定本人未删除DRAFT→校验所有新引用→有新附件时保存新文件并登记回调→更新资源和关联→提交。未传file则保留原文件；传空file会拒绝。
3. 回滚：数据库资源/关联回滚后，afterCompletion清理本次新文件；不动旧附件。
4. 替换成功：数据库提交后，afterCommit才清理旧的未引用草稿文件；不存在提前覆盖旧文件的操作。
5. 草稿删除：只写deleted_at和updated_at；保留资源行、当前文件和关联，后端详情/编辑/列表均不可再访问。物理空间清理策略留待明确授权，不提供永久删除接口。

边界：数据库和文件系统并非分布式原子事务。进程崩溃、磁盘清理失败或提交结果UNKNOWN仍可能需要人工核对；UNKNOWN时不盲目删新文件。清理失败记录服务端日志，不把已提交的保存伪报为失败。实际运行期间未发生清理失败。

## 5. 新接口与页面

| 接口 | 实际行为与权限 |
|---|---|
| GET /api/teacher/resources | TEACHER，本人未删除DRAFT分页；keyword/courseId/categoryId/status |
| GET /api/teacher/resources/upload-policy | TEACHER，只返回maxSizeBytes/allowedExtensions |
| GET /api/teacher/resources/{id} | TEACHER本人DRAFT详情，含课程/分类和多个元素 |
| POST /api/teacher/resources | TEACHER+CSRF，multipart metadata+file，201 |
| PUT /api/teacher/resources/{id} | TEACHER本人DRAFT+CSRF，完整metadata和可选替换file |
| DELETE /api/teacher/resources/{id} | TEACHER本人DRAFT+CSRF，软删除，200统一响应 |

metadata字段只有title、description、courseId、categoryId、elementIds；未知字段（含伪造创建者或状态）、尾随JSON和小数ID均拒绝。课程/分类ID必须正整数；元素最多接受1000个输入ID作为请求规模保护（并非业务要求必须标注1000个），去重后逐个检查。分页page≥1，1≤size≤100，keyword最多200字符；状态仅空或DRAFT。

URL与方法级均限制TEACHER，服务层再次检查角色。归属条件在SQL中绑定当前教师ID；其他教师或不存在资源统一404，不泄露对象是否存在；ADMIN/STUDENT为403，未登录401，有效会话缺CSRF403，非法引用/文件400，超限413，错误请求Content-Type415，非草稿状态409。

前端新增4个路由、3个组件：我的资源 `/my-resources`；新建 `/my-resources/new`；详情 `/my-resources/:id`；编辑 `/my-resources/:id/edit`。菜单只对教师显示，路由守卫限制角色；列表支持搜索、课程/分类/草稿筛选和分页。删除使用页面内确认，未使用原生confirm。表单复用第二阶段三个options API；草稿元素可不选、多选，真实数据回显，停用历史数据作标注。详情展示附件元数据，不放未实现的按钮。

`api/client.js`仅扩展FormData传输分支，仍复用原CSRF和Session逻辑；不手动设置multipart boundary，不更换认证架构。
