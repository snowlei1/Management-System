# 01 需求分析

## 1. 基线与边界

课题名称：基于SpringBoot的课程思政教学资源管理系统设计与实现。

本设计以指导教师确认的任务书、开题报告及本轮明确的范围为需求基线。系统面向管理员、教师、学生三类用户，管理课程基本信息、课程思政元素和教学资源，并支持资源提交审核、内部发布、检索、预览、下载、收藏、必要使用记录和描述性统计。

课程模块不承担选课、排课、成绩和考试。资源共享仅发生在系统内部。系统不包含社交分享、AI、大模型、知识图谱、智能推荐、用户画像、预测分析，也不引入微服务、Redis、Elasticsearch、MQ 或 Kubernetes。

## 2. 业务参与者

| 参与者 | 业务目标 | 数据范围 |
|---|---|---|
| 管理员 | 维护用户、课程、思政元素与资源分类；审核资源；管理已发布资源；查看基础统计 | 全部基础数据、待审核资源、审核记录、已发布资源 |
| 教师 | 创建、编辑、标注、提交本人资源；检索、预览、下载、收藏已发布资源 | 本人各状态资源及其审核意见；全站已发布资源 |
| 学生 | 检索、查看、预览、下载、收藏已发布资源 | 全站已发布资源；本人的收藏与使用记录 |

没有游客资源入口。停用用户不能登录。教师只能更改自己创建且处于草稿或审核驳回状态的资源。学生不能上传或审核资源。

## 3. 关键业务规则

1. 每个教学资源必须关联且只关联一门课程；一门课程可以有多条资源。
2. 一个资源可以关联多个思政元素；思政元素由管理员统一维护，资源与元素是多对多关系。`DRAFT` 草稿允许 0..N 个元素；提交/重提审核时必须至少有 1 个元素，且所有关联元素有效。第四阶段正式落实提交校验。
3. 管理员维护资源分类；分类用于资源组织、检索和描述性统计，不承担复杂标签体系。
4. 资源状态为 `DRAFT`、`PENDING`、`APPROVED`、`REJECTED`。创建时为草稿；教师提交后待审核；管理员通过时立即在系统内部发布；驳回时记录原因，教师修改后重新提交。
5. 普通资源可见条件为 `status='APPROVED' AND deleted_at IS NULL AND published_at IS NOT NULL AND withdrawn_at IS NULL`，资源中心只供 TEACHER/STUDENT 使用。本人资源由创建教师通过专属入口查看；管理员通过独立审核入口查看已提交过的 `PENDING/REJECTED/APPROVED` 资源、审核历史和审核附件，从未提交的 `DRAFT` 不开放。管理员审核查看不属于普通资源使用。
6. 待审核和已通过内容不能由教师直接修改。驳回后编辑仍保持 `REJECTED`，由明确重提动作进入 `PENDING`。审核通过资源的教师侧修改暂不开放；后续改版须先确认版本/重新审核规则。
7. 教师可软删除自己的草稿或驳回资源；待审核资源不能删除。2026-10-20用户确认新增管理员下架/恢复：仅对已审核通过且发布过的资源操作，下架原因必填，恢复原始内容；不修改审核状态、首次发布时间、附件及审核历史。教师不可借下架编辑已审核内容；内容改版、撤回审核和版本管理仍未开放。
8. 已被资源引用的课程、思政元素、分类不能物理删除；管理员可停用，已有历史引用保持可追溯。
9. 收藏沿用同一用户/资源唯一关系及 `active` 状态，重复收藏/取消幂等，不物理删除。每次成功 GET 普通已发布资源详情记一条浏览事件，打开和刷新均可产生事件；列表、预览、收藏/取消、教师专属详情和管理员审核读取不记普通浏览。下载在身份、可见性和文件校验完成、准备正常返回附件时记一条请求事件，不代表客户端完整接收。HEAD 详情/下载不记事件。user_id 均取自 Session；这些事件不是独立访问人数。
10. 后端必须再次校验身份、角色、资源归属和状态；前端隐藏菜单或按钮不构成权限控制。
11. 私人一级收藏夹仅教师/学生本人可维护；移除目录只将收藏归回未分组，不删除资源或取消收藏。
12. 封面及作者、来源、使用限制说明均可选；仅本人草稿/驳回资源可修改。封面不增加普通使用事件，系统内可用不等于获得对外使用授权。
13. 教师/学生仅对当前可用资源提交私人问题反馈，同人同资源只允许一条待处理反馈。管理员以已处理/不予采纳及必填说明结案；处理不自动下架，结论不可覆盖，资源下架后反馈仍可追溯。

当前统计口径（第六阶段基础上加入发布治理）：用户包含停用账号，角色数与启停数分别展示；课程、元素、分类显示总数与启用数。当前资源排除软删除；已发布数要求APPROVED、未删除、published_at非空且withdrawn_at为空，下架数与软删除数分别列出。课程/分类/元素分布只计当前已发布资源，保留停用基础数据关联及零项；多元素合计可超过资源数。浏览/下载累计包含软删除及下架历史事件；当前收藏只计active=TRUE且资源满足四个已发布条件的关系，不同范围不共用分母。

统计概览及全部普通入口采用规则5的四条件；基础数据停用不自动下架已通过资源，下拉选项只返回启用基础数据。统计仅为本地开发/测试库的描述性统计，不提供UV、趋势、排名、推荐或预测。

## 4. 功能需求与验收边界

| 编号 | 功能 | 最小可验收行为 |
|---|---|---|
| FR-01 | 登录与权限 | 三类有效用户登录；停用用户拒绝；越权接口拒绝 |
| FR-02 | 用户管理 | 管理员新增、修改、停用用户并指定固定角色 |
| FR-03 | 课程管理 | 管理员维护课程基本信息；资源只绑定一门有效课程 |
| FR-04 | 思政元素管理 | 管理员维护元素；教师给本人资源标注多个有效元素 |
| FR-05 | 资源分类 | 管理员维护分类；教师给资源选择分类 |
| FR-06 | 资源建设 | 教师上传文件、填写元数据、保存和编辑本人草稿/驳回资源 |
| FR-07 | 审核 | 提交、通过、驳回、查看驳回原因、修改重提；保存审核历史 |
| FR-08 | 内部共享 | 仅对已发布资源提供组合检索、详情、预览、下载 |
| FR-09 | 收藏与记录 | 教师/学生收藏或取消；记录必要的浏览、下载行为 |
| FR-10 | 基础统计 | 管理员查看用户、课程、资源、审核状态、分类、元素及使用次数统计 |
| FR-11 | 私人收藏整理 | 本人一级目录；移动、重命名、移除目录不损坏收藏关系 |
| FR-12 | 封面与来源 | 草稿/驳回可选维护，提交后只读；受控图片存储 |
| FR-13 | 资源问题反馈 | 本人提交与查询、管理员处理；私有、可追溯、不公开评论 |
| FR-14 | 发布治理 | ADMIN下架/恢复原始已通过资源；不引入版本编辑 |

## 5. 非功能要求

- 安全：密码只保存安全散列；校验请求参数、上传类型与大小；文件下载和预览不能绕过权限；异常响应不泄漏内部路径或数据库细节。
- 一致性：状态转换和审核记录在同一事务内完成；资源与课程、分类、元素的引用符合外键约束。
- 可维护性：前后端分层，业务规则在服务层集中处理；使用清晰命名、统一响应与统一异常处理。
- 可用性：用户能区分资源状态、操作结果和审核驳回原因；检索可处理无结果和无效筛选条件。
- 可验证性：功能、权限、状态、边界输入和异常操作均有可重复的测试用例。现阶段不预设并发、性能、用户规模或教学效果指标。
