# 04 业务流程与关键时序

## 1. 资源生命周期

提交与审核属于状态转换，必须由后端在事务中校验。管理员通过时同时写审核记录、置为 `APPROVED` 并写 `published_at`；驳回时写审核原因并置为 `REJECTED`。删除/下架只写 `deleted_at`，不物理清除审核历史。

```mermaid
stateDiagram-v2
    [*] --> DRAFT: 教师创建
    DRAFT --> DRAFT: 本人编辑/标注/换文件
    DRAFT --> PENDING: 本人提交并通过完整性校验
    PENDING --> APPROVED: 管理员审核通过/内部发布
    PENDING --> REJECTED: 管理员驳回并记录原因
    REJECTED --> REJECTED: 本人修改
    REJECTED --> PENDING: 本人重新提交
    DRAFT --> ARCHIVED: 本人软删除
    REJECTED --> ARCHIVED: 本人软删除
    APPROVED --> ARCHIVED: 管理员下架
    note right of APPROVED
      仅未下架资源可供普通用户检索和使用
    end note
    note right of ARCHIVED
      逻辑删除标记，不是第五种审核状态
    end note
```

`ARCHIVED` 只是图中的终止可见性节点，对应 `deleted_at IS NOT NULL`，不是资源审核状态枚举值。教师不得直接编辑待审核和已通过的资源。

第三阶段只实现 `DRAFT → DRAFT` 和 `DRAFT → ARCHIVED`，不实现提交或审核。草稿允许 0..N 个思政元素；将来 `DRAFT/REJECTED → PENDING` 时须至少 1 个有效元素，不能把该条件提前强加给草稿保存。

### 审核关键时序（Mermaid）

```mermaid
sequenceDiagram
    actor T as 教师
    participant V as Vue页面
    participant C as ResourceController
    participant S as ResourceService
    participant DB as MySQL
    actor A as 管理员
    T->>V: 提交本人草稿/驳回资源
    V->>C: POST /api/resources/{id}/submit
    C->>S: submit(currentUser,id)
    S->>DB: 锁定资源并校验归属、状态、完整性
    alt 校验通过
        S->>DB: 更新为PENDING并递增提交轮次
        S-->>V: 成功
    else 校验失败
        S-->>V: 统一业务错误
    end
    A->>V: 查看待审核资源并给出结论
    V->>C: POST /api/audits/{id}/decision
    C->>S: decide(currentAdmin,id,decision,reason)
    S->>DB: 锁定资源并校验PENDING
    S->>DB: 同一事务写AuditRecord和资源状态
    alt 通过
        S->>DB: APPROVED + published_at
    else 驳回
        S->>DB: REJECTED + 驳回原因
    end
    S-->>V: 审核结果
```

## 2. 登录与权限判断

```mermaid
flowchart TD
    A[用户输入账号和密码] --> B[后端校验账号、密码散列和用户状态]
    B -->|失败/停用| X[返回统一认证错误]
    B -->|成功| C[建立身份凭据并读取固定角色]
    C --> D[前端按角色展示菜单]
    D --> E[用户发起业务请求]
    E --> F[后端校验凭据与角色]
    F -->|未通过| Y[401或403]
    F -->|通过| G[校验资源归属与审核状态]
    G -->|未通过| Y
    G -->|通过| H[执行业务并返回统一响应]
```

## 3. 检索与查看

```mermaid
flowchart TD
    A[已登录用户输入关键词/课程/分类/元素] --> B[校验筛选项并构建组合查询]
    B --> C[固定限定APPROVED且未下架]
    C --> D[返回分页结果]
    D --> E[用户打开详情]
    E --> F[后端再次校验可见性]
    F -->|通过| G[返回详情并记录公开浏览]
    F -->|拒绝| H[不返回文件路径或内容]
```

## 4. 收藏

```mermaid
flowchart TD
    A[教师或学生点击收藏/取消] --> B[后端校验角色及已发布状态]
    B -->|不通过| X[拒绝请求]
    B -->|通过| C{是否已有收藏记录}
    C -->|无| D[新建有效收藏]
    C -->|有| E[切换有效状态]
    D --> F[返回当前收藏状态]
    E --> F
```

收藏表按 `(user_id, resource_id)` 唯一；取消收藏改变当前有效状态。统计“收藏量”只计有效收藏，避免重复收藏使计数膨胀。

## 5. 下载

```mermaid
flowchart TD
    A[用户请求下载] --> B[校验登录与角色]
    B -->|失败| X[401/403]
    B -->|通过| C[查询资源并校验APPROVED且未下架]
    C -->|失败| X
    C -->|通过| D[校验实际文件存在且可读]
    D -->|失败| Y[统一资源错误，不记下载]
    D -->|通过| E[准备附件响应]
    E --> F[写入下载记录]
    F --> G[开始输出文件]
```

下载记录表示通过授权且文件已准备输出的请求，不推断用户是否完整保存了文件。预览同样经过权限和文件检查，但不计作下载。
