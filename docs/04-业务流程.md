# 04 业务流程与关键时序

## 1. 资源生命周期

提交与审核属于状态转换，必须由后端在事务中校验。管理员通过时同时写审核记录、置为 `APPROVED` 并写 `published_at`；驳回时写审核原因并置为 `REJECTED`。教师本人草稿/驳回软删除只写 `deleted_at`，不物理清除审核历史；管理员下架、撤回及版本管理不在当前范围内。

```mermaid
stateDiagram-v2
    [*] --> DRAFT: 教师创建
    DRAFT --> DRAFT: 本人编辑/标注/换文件
    DRAFT --> PENDING: 本人提交并通过完整性校验
    PENDING --> APPROVED: 管理员审核通过/内部发布
    PENDING --> REJECTED: 管理员驳回并记录原因
    REJECTED --> REJECTED: 本人修改
    REJECTED --> PENDING: 本人重新提交
    DRAFT --> ARCHIVED: 本人软删除
    REJECTED --> ARCHIVED: 本人软删除
    note right of APPROVED
      APPROVED且未删除且published_at非空
      才可供教师/学生检索和使用
    end note
    note right of ARCHIVED
      逻辑删除标记，不是第五种审核状态
    end note
```

`ARCHIVED` 只是图中的终止可见性节点，对应 `deleted_at IS NOT NULL`，不是资源审核状态枚举值。教师不得直接编辑待审核和已通过的资源。

第三阶段只实现 `DRAFT → DRAFT` 和 `DRAFT → ARCHIVED`，不实现提交或审核。草稿允许 0..N 个思政元素；将来 `DRAFT/REJECTED → PENDING` 时须至少 1 个有效元素，不能把该条件提前强加给草稿保存。

第四阶段已经实现DRAFT/REJECTED→PENDING以及PENDING→APPROVED/REJECTED；编辑驳回资源保持REJECTED。提交前锁定本人资源、重新验证元数据、启用课程/分类/全部元素与实际附件；成功提交才递增轮次。审核锁定资源，核对PENDING及页面轮次；过期页面/重复审核409。通过和驳回的历史/状态更新同事务，发布只发生在真正通过时。

### 审核关键时序（Mermaid）

```mermaid
sequenceDiagram
    actor T as 教师
    participant V as Vue页面
    participant C as ResourceController
    participant S as ResourceService
    participant DB as MySQL
    actor A as 管理员
    T->>V: 提交本人草稿/驳回资源
    V->>C: POST /api/teacher/resources/{id}/submit
    C->>S: submit(currentUser,id)
    S->>DB: 锁定资源并校验归属、状态、完整性
    alt 校验通过
        S->>DB: 更新为PENDING并递增提交轮次
        S-->>V: 成功
    else 校验失败
        S-->>V: 统一业务错误
    end
    A->>V: 查看待审核资源并给出结论
    V->>C: POST /api/admin/resource-reviews/{id}/approve或reject
    C->>S: decide(currentAdmin,id,expectedRound,decision,reason)
    S->>DB: FOR UPDATE锁定并校验PENDING及轮次
    S->>DB: 同一事务写AuditRecord和资源状态
    alt 通过
        S->>DB: APPROVED + published_at
    else 驳回
        S->>DB: REJECTED + 驳回原因
    end
    S-->>V: 审核结果
```

## 2. 登录与权限判断

```mermaid
flowchart TD
    A[用户输入账号和密码] --> B[后端校验账号、密码散列和用户状态]
    B -->|失败/停用| X[返回统一认证错误]
    B -->|成功| C[建立身份凭据并读取固定角色]
    C --> D[前端按角色展示菜单]
    D --> E[用户发起业务请求]
    E --> F[后端校验凭据与角色]
    F -->|未通过| Y[401或403]
    F -->|通过| G[校验资源归属与审核状态]
    G -->|未通过| Y
    G -->|通过| H[执行业务并返回统一响应]
```

flowchart TD

## 4. 收藏

```mermaid
flowchart TD
    A[教师或学生点击收藏/取消] --> B[后端校验Session角色、CSRF及三个公开条件]
    B -->|不通过| X[拒绝请求]
    B -->|通过| C{收藏还是取消}
    C -->|收藏| D[唯一键UPSERT为active=true]
    C -->|取消| E[UPDATE为active=false，无关系也幂等成功]
    D --> F[返回当前收藏状态]
    E --> F
```

收藏表按 `(user_id, resource_id)` 唯一；取消收藏改变当前有效状态。统计“收藏量”只计有效收藏，避免重复收藏使计数膨胀。

第五阶段真实MySQL并发验证两次同时收藏均成功且最终一条关系。资源行先加共享锁保证本次可见性，不提前给收藏行加共享锁，避免UPSERT锁升级竞争。当前没有下架业务；我的收藏仍固定排除非公开/已软删除资源。

## 5. 下载

```mermaid
flowchart TD
    A[教师/学生请求受保护下载URL] --> B[校验Session登录与角色]
    B -->|失败| X[401/403]
    B -->|通过| C[SQL限定APPROVED且未删除且published_at非空]
    C -->|失败| X
    C -->|通过| D[校验受控路径、可读性、大小、类型及基本内容特征]
    D -->|失败| Y[统一资源错误，不记下载]
    D -->|通过| E[准备附件响应]
    E --> F[事务内写下载请求事件，HEAD不记]
    F --> G[开始输出文件]
```

下载记录表示通过授权且文件已准备输出的请求，不推断用户是否完整保存了文件。预览同样经过权限和文件检查，但不计作下载。

第五阶段普通资源详情每次成功GET记一条事件，刷新可新增，不是UV。列表、预览、收藏/取消及管理员审核详情/附件不追加普通使用事件。详情/下载事件插入失败时事务回滚，不能只凭前端点击推断落库成功。

## 6. 管理员基础统计

```mermaid
flowchart TD
    A[进入统计概览或刷新] --> B[后端从Session校验ADMIN]
    B -->|未登录/越权| X[统一401/403]
    B -->|通过| C[开启只读REPEATABLE_READ事务]
    C --> D[固定9条批量聚合SQL]
    D --> E[用户和基础数据总数/状态数]
    D --> F[当前资源状态及独立软删除数]
    D --> G[历史浏览/下载及当前公开收藏]
    D --> H[已发布资源课程/分类/元素分布]
    E --> I[统一VO返回卡片及分页表格]
    F --> I
    G --> I
    H --> I
```

统计只读、不新增使用事件；三个已发布条件与资源中心一致。零资源基础数据仍返回，停用不抹除历史分布。多元素关联不是互斥分类，事件数不是访问人数或教学效果。
