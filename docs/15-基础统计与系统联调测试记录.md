## 3. 统计指标和SQL口径

统一公开资源条件记为P：

```sql
r.status = 'APPROVED'
AND r.deleted_at IS NULL
AND r.published_at IS NOT NULL
```

| 指标 | 实际查询口径 |
|---|---|
| 用户总数 | app_user与role关联，COUNT(*)，含停用账号；外键保证角色存在 |
| 管理员/教师/学生数 | 按role.code条件SUM；三种角色互斥 |
| 启用/停用用户数 | status为ACTIVE/DISABLED的条件SUM |
| 课程、元素、分类总数与启用数 | 对应表COUNT(*)及SUM(status='ACTIVE')，总数含INACTIVE |
| 当前资源总数 | SUM(deleted_at IS NULL) |
| DRAFT/PENDING/REJECTED | SUM(deleted_at IS NULL AND status=对应状态) |
| 已发布APPROVED | SUM(P)，不把有状态但缺发布时间的异常数据当成已发布 |
| 独立软删除数 | SUM(deleted_at IS NOT NULL)，不混入当前资源总数 |
| 浏览累计事件 | browse_record COUNT(*)，包含软删除历史，不是访问人数 |
| 下载累计请求事件 | download_record COUNT(*)，包含软删除历史，不证明客户端完整保存 |
| 当前有效公开收藏 | favorite关联resource，f.active=TRUE且P；inactive及不再公开的关系排除 |
| 课程/分类资源分布 | 基础表LEFT JOIN满足P的资源，按基础id/name/status GROUP BY，COUNT(r.id) |
| 元素关联分布 | 元素LEFT JOIN关联表，再LEFT JOIN满足P的资源，GROUP BY元素，COUNT(r.id) |

COUNT/SUM空值采用COALESCE返回0。三类分布包含零资源项以及停用基础数据的历史关联；基础数据停用不自动撤下已发布资源。课程和分类每资源各一个，所以分布合计对应已发布资源数；元素多对多，元素关联合计可以大于资源数。

资源总数和四状态合计的一致性在当前有效数据中通过；若未来出现APPROVED但无published_at，统计不会掩盖异常，应通过一致性检查处理，而不是伪造已发布计数。

固定9条查询：用户1、基础数据3、资源1、使用1、分布3。Service以只读REPEATABLE_READ事务返回同一快照。GROUP BY批量聚合，无按课程或资源逐行调用SQL的N+1。表名/外键列名只来自固定内部常量，不接受客户端输入；其他业务请求值沿用参数化SQL。

实际EXPLAIN：课程分布使用idx_resource_public；元素分布使用idx_relation_element_resource及资源PRIMARY。聚合排序存在temporary/filesort。没有经过吞吐或并发性能基准测试，不把EXPLAIN解释成性能证明，也无新增索引的实测必要性。
